Settings

The auto-fix agent triages logged site errors and asks Claude Code to fix the unresolved ones. It runs one at a time, capped by the limits below. Changes here take effect on the next cron tick.
Pause Auto-Fix
When on, the agent is fully paused — no triage, no Claude runs. (Separate from the temporary pause set automatically during VS Code editing sessions.)
Run Interval
min
How often the agent checks for unresolved errors. Minimum 5 minutes.
Max Run Time
sec
A single fix attempt is killed if it runs longer than this. 60–3600s (1800 = 30 min).
CPU Cap
% of 1 core
Hard CPU ceiling for the Claude process (systemd CPUQuota). 70 = 0.7 of one core.
Memory Cap
MB
Hard memory ceiling (systemd MemoryMax). The process is killed if it exceeds this.
Max Fix Attempts
After this many failed attempts on one error, it is retired for human review instead of retried forever.

Authentication

The agent signs in with the Claude subscription session — never the API key. When that session expires it stops fixing anything until you supply fresh credentials. A long-lived token is the durable fix; a pasted .credentials.json works too but expires sooner.

On any machine with a browser, run claude setup-token, finish the browser login, and paste the printed token here. It authenticates as your subscription and does not expire for ~1 year, so this exact breakage won't recur.

From a machine where claude login succeeded, paste the full contents of ~/.claude/.credentials.json (must contain claudeAiOauth.accessToken). Its access token expires sooner than a setup-token.
